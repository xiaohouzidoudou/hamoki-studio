# Hamoki Studio Backend V2 · 隔离测试版

该目录是新增的 Fastify + Node.js 24 内置 SQLite 后端。原自由画布前端保持不变，旧服务 `127.0.0.1:8028` 的原有数据没有迁移或修改。

## 本地启动
- Node.js 24+；`npm install`；`node src/index.ts`。
- 默认只监听 `127.0.0.1:8048`，打开 `http://127.0.0.1:8048/login`。
- 首次启动会创建并仅在首次控制台输出随机管理员激活码，持久化的是哈希。用户以激活码自行设置固定账号 `hamoki` 的密码；管理员未激活前先不要公开暴露新网关。
- 账号和密钥数据库在 `backend-v2/data/`，密钥文件 `master.key` 必须仅供服务所有者访问。它与 SQLite 数据库配套，一起做可恢复备份，绝不可放进 GitHub。
- 配置项：`STUDIO_PORT`（默认 8048）、`STUDIO_HOST`（默认 127.0.0.1）、`STUDIO_DATA_DIR`、`STUDIO_MAX_USERS`（默认 12）、`STUDIO_SECURE_COOKIES=1`（HTTPS 正式站必选）、`SUB2_BASE_URL`。
- 与 Sub2 部署在同一台服务器时：`SUB2_BASE_URL=http://127.0.0.1:51808`，并设置 `SUB2_ALLOW_PRIVATE_HTTP=1`。Sub2 仍只需监听本地回环，不需要开放公网端口。前端只能与 Studio 后端同源交互。
- 每个已登录用户使用独立本地 Node worker、隔离的 `data/users/<id>` 目录和 1 GiB 原图/缩略图配额；不得直接将 worker 或旧 8028 服务映射到公网。建议小规模用户，不设计为大规模多租户平台。

## 账号和 Sub2
- 普通账号开放用户名/密码注册；`hamoki` 用户名受保护，无法公开注册抢占。
- 管理员可查看用户、用管理员密码复核后禁用和重置普通用户密码；临时密码 24 小时有效，首次登录必须修改。
- Sub2 邮箱/密码仅用于一次性 HTTPS 或可信本地连接认证，不保存 Sub2 密码；访问和刷新令牌以及生成用专属 Key 存储为 AES-GCM 密文。
- 用户通过 Sub2 登录后尝试创建专用 Key、查询模型并添加其独立的画布服务商；不能确认生图模型时不宣称可用。
- 余额查询实时读取 Sub2，不创建另一套余额账本。支持现有用户在设置页绑定自己的 Sub2。
- 普通本地注册账号如果没有 Sub2，也可以按原有功能自行设置其他 API。

## 付费任务
- 原有 `/api/jobs` 沿用画布旧队列及 429 限流重试、504/524 扣费不确定保护。
- 新增 Sub2 异步任务账本：`POST /api/account/sub2/jobs` 接收 `requestId,model,prompt,size`；同一用户的 `requestId` 只提交一次。GET `/api/account/sub2/jobs/:id` 查询已保存上游 ID，进程重启后仍能查询，不重复生图。
- 已发送但没有可靠上游 ID 的请求标记 `uncertain`，绝不自动重发付费请求。异步接口能否使用取决于实际 Sub2 图片分组及对象存储配置；实际部署未付费联调。
- 现有画布旧 `/api/jobs` **尚未改为新异步任务账本**；需要额外整合和真实计费测试才能完成透明接入。当前独立 API 供后续联调使用。

## 测试与现存限制
- `node --test tests/*.test.mjs`：涵盖管理员激活、注册、隔离、密码重置、模拟 Sub2 账号/余额/模型/专用 Key、任务幂等和异常断线，以及默认 SSRF 防护。3 组通过。
- 原项目的旧全量测试在本次之前已有失败，包括引用已不存在 `workspace.js` 的测试，不通过不能误报为新后端导致。
- 工作电脑上新后端仅本机访问，不是公网正式站。现网 Sub2 的正式用户认证/余额/图像收费接口尚未联调。
- 默认 Fastify API 子系统不是独立前端工程；画布原始文件未改动。旧 `lib/upstream.js` 唯一小幅后端调整：仅在显式 `STUDIO_TRUSTED_SUB2_URL` 被设置时，允许精确本地 Sub2 的 `/v1/` 受信任接口，其余所有内网地址仍被拒绝。
