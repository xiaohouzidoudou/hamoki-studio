# Hamoki Studio · 从零重建（Alpha）

**这是不继承旧版功能和数据的新工程。** 用户决定废弃旧版无限画布、Cowart、旧账号、图片、项目历史和中转站配置；旧版保存在 GitHub 分支 `archive/pre-rebuild-20261026`。

## 当前实现
- 游戏活动类型、美术风格、游戏类型、玩法类型、节日主题、平台比例参数选择。
- 规则驱动的专业游戏 UI 提示词补全：布局、功能、材质、光影、文字预留和负面约束。
- 提示词编辑与复制；可选 OpenAI 兼容图片生成 API（由**服务端**环境变量提供）。
- 无用户账号、无数据库、无文件上传、无图片和历史存储，不读取旧版数据卷。
- 下一阶段再加入可配置文字模型扩写，并以真实游戏 UI 生成质量评测替代主观堆功能。

## 使用
`node server.js`，默认只监听 `127.0.0.1:8035`。
`npm test` 验证提示词生成。
可选服务端环境变量：`IMAGE_API_URL`（完整 HTTPS 图片生成接口地址）、`IMAGE_API_KEY`、`IMAGE_MODEL`。各中转站的参数支持情况不同，请按实际接口适配。**不要把 Key 填在浏览器或提交到 Git。**

## 上线保护
1. **先核实线上宿主机及旧 Docker 卷，制作独立于原卷的备份并进行恢复抽验。**
2. 核实旧网站域名、反代、DNS、Docker Compose 项目、卷和其他站点是否共享依赖。
3. 先在**独立容器、端口和数据环境**验收新版本；不要复用旧数据卷。
4. 删除旧站点的账号、图片、项目、密钥数据前须确认独立备份和恢复能力；不要运行 `docker compose down -v` 或全局 prune。
5. 原站点与 main 保持不变，直到备份与线上影响确认完成。
