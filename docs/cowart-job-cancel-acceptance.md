# Cowart 取消与请求结果验收

关联 Issue #24。复用现有账号任务接口，不提供自动付费重试，也不把取消或 HTTP 拒绝当作退款证明。

## 行为

- Cowart 已知排队/运行任务提供「取消此任务」，确认提示明确上游可能继续处理或已计费。按钮请求期间禁用，用户拒绝确认不会发送请求。
- 取消请求失败或响应丢失时重新查询原任务，不创建新生图。服务器取消接口对已经取消的同一任务返回原结果；完成任务取消返回 409，不覆盖已完成状态。
- 失败/取消/中断后，需要明确开启下一轮才能再次提交。运行中取消且费用未知时，开启下一轮还需确认已核对原任务与中转站记录。
- 服务器保存图片上游调用阶段、HTTP 状态及结果证据，重启后保留。旧任务证据不足时保守显示未知；已保存上游异步 ID 的查询失败不当作初始提交被拒绝。
- 图片返回后本地保存失败归为「上游已返回图片」，不能当作没有产生费用。仅本地输入检查失败、尚未调用图片上游的任务可显示未调用；这不包含先前文字或视觉分析费用。
- Cowart 请求显式关闭 429 自动重发，持久 Cowart 任务也不走 429 自动重发分支；其他既有队列的默认策略保留。手动重试继续复用原有再次付费确认与防重复尝试逻辑，新尝试清空旧请求证据。

| requestOutcome | 证据含义 |
| --- | --- |
| not_sent | 当前图片任务尚未调用图片上游 |
| http_rejected | 收到明确 HTTP 拒绝；费用仍需核对账单 |
| result_received | 上游图片已返回；本地是否完成保存另看任务状态 |
| unknown | 超时、断线、取消、重启中断或证据不足，不能确定上游结果 |

## 验证

- 本机全量 165 项测试、Cowart 构建通过，精确提交及 CI 以任务 PR/Issue 为准。
- 真实临时账号网关和真实协议适配器连接本地模拟上游：排队取消零上游调用、运行取消后不入历史、重复取消幂等、完成后取消 409；400/429 拒绝、断线未知、本地文件缺失未调用、429 恰好一次调用。
- 重启保留取消和拒绝证据，手动重试需要明确确认，新的排队尝试没有旧 HTTP 状态。
- Chromium 使用真实临时网关/队列/模拟上游，验证取消确认拒绝、取消响应丢失后按原 ID 查询、运行取消按钮禁用和再次提交阻止。恰好两个图片任务、一次上游调用、两次取消请求。截图已检查，CI 保留 `job-controls.png`。
- 原有模拟生成、两轮编辑、失败保存刷新恢复仍通过，图片任务恰好提交三次。

## 限制与接手

未部署、未调用真实付费模型；不能证明真实中转站停止执行、退款或账单正确。断线/超时仍需用户核对中转站任务与账单，未增加自动重新生图。

需与 PR #26 的服务端任务恢复一起集成验证：取消结果与终态确认复用原任务身份，不应绕过其待处理任务门禁。其他待审 PR 也需组合 CI 与隔离 QA，实际部署 SHA 必须单独确认。

回滚可撤销代码，已有任务中的新增证据字段向后兼容；不重置数据或更改正式环境。
