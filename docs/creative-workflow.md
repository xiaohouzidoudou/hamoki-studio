# AI 美术协同工作流（开发版）

目的：策划 Word 文档与游戏已有 UI 风格参考图作为输入，在 Hamoki Studio 中完成「文档提取 → 风格分析 → 原型布局分析 → 美术总监创作方案 → 人工确认生成 → 视觉质检」。生成后交给用户审核，不包含 Unity 上传、切图和自动商业发布。

## 操作

1. 登录 Hamoki Studio，打开一个创作项目，先把游戏实际 UI 截图添加到画布。
2. 左侧点击「AI 美术工作流」，上传单个 .docx（不超过 12MB）；Word 文字、表格和内嵌原型图提取后会留在本项目画布。文件不直接发到 AI，上游仅收到被选取的图像和文档摘录。
3. 选择一张文档布局原型与最多五张游戏风格图；配置一个支持文字的模型（GPT/DeepSeek）和一个支持图像理解的模型（GPT/Gemini）。补充创作要求可选。
4. 点击「开始 AI 协同分析」并确认费用：风格分析师、原型分析师、美术总监按阶段工作，保存实际输出与错误状态。每阶段成功会持久化在当前账号项目中。
5. 用户检查 AI 总监方案，点击「送入画布生图操作台」；系统将风格图标为「画风」，文档原型标为「造型」，由**现有画布生图接口**处理（请选 GPT Image 2.5 或 Gemini 香蕉，并自行确认生图费用）。
6. 生成完成后回到工作流，选择该项目作品，手动执行风格+布局三图质检；如有问题将报告连同原参考交回原生图框，再手动生成。

## 边界及待验证项

- 本版本将开源 `ai_asset` 的 Style/TARGET/CHECK 工作原则**适配**成项目级任务说明，并非直接运行其完整 110KB primer。参考规则采用 MIT 许可（Bao Tran, 2026, https://github.com/tnbao91/ai_asset）；亦参考同为 MIT 许可的 game-ui-design-workflow（https://github.com/guiguiyan930-source/game-ui-design-workflow）。
- 工作流程不用 Codex 常驻；分析由后端调用模型接口，生图经现有队列。自动多轮返工**尚未开启**，避免不受控扣费。
- 对视觉模型的多图理解能力与生成模型的实际布局还原能力，需要在独立测试站接入真实模型并用用户确认的游戏 UI 截图检验；程序级测试使用模拟模型，不能代表真实绘制质量。
- 当前仅支持 DOCX 和 PNG/JPEG/WebP 内嵌图，不会自动 OCR 图片文字、无跨多个文档聚合，也不能保证复杂 Word 图表百分之百还原。默认保护选定风格和 Word 原型源图不被配额清理。
- 上游模型接口能力各异，OpenAI 视觉分析走 Chat Completions；Gemini 走 generateContent；单纯的图片生成端点不能冒充文字视觉模型。
- 后台可持续跨弹窗执行并查询状态，服务重启会标记中断；可能存在上游已扣费，故不会无条件重试。项目备份可携带本项目工作流，并在导入时重映射图片关联，不迁移账号模型路由。
- 开发时应在独立环境中验证；不得把真实策划资料、参考图或任何 API Key 放入公开 GitHub 仓库。
