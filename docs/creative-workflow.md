# Hamoki Studio 游戏 UI 多 AI 美术工作流（测试版）

本功能附加于现有 Hamoki Studio，保留原无限画布、项目、登录和图片模型队列。

## 使用方式

1. 左侧打开「AI 美术工作流」，连续或批量上传 Word DOCX，单份最多 12MB，最多 12 份；重复文件按 SHA256 拒绝。Word 文字、表格、章节、原型图会提取到当前账号项目，不覆盖已有文档，上传不会扣除 AI 额度。
2. 免费按标题和图文顺序建立页面任务，缺原型会显示待补充。也可以点击「AI 智能拆页」调用一次文字模型，按文档真实出现的页面名称重新归纳，需人工确认模型费用。
3. 页面清单按页选择和编辑要求，原型图片只能选该页文档里的图片，不自动错配。不同页面保留各自的提示词和视觉质检结果。
4. 在画布选择 0–5 张真实游戏 UI 风格图；AI 分析后保存为整个项目的 Style DNA，可以锁定并让后续页面复用。更换风格图会要求确认清空旧风格与旧设计方案。
5. 文字模型可选 GPT/DeepSeek 等，视觉模型必须真正支持看图。点击「分析当前页面」或「批量完成缺失页面方案（最多 8 页）」时，再人工确认可能的付费调用。风格识图、原型分析、美术总监按步骤执行并保存到所选页面；没有原型图则标注不确定性。
6. 点击「送入画布生图操作台」，当前页的文字方案、风格图和原型图分别带到原操作台。图片生成由用户自行选择 GPT Image 2.5 或 Gemini 香蕉，点击生成才调用付费图片模型。
7. 生成结束后可以对照风格、原型、输出图做视觉质检，返回返工建议；没有自动无限重试，最终由用户审核。

## 限制与安全

- 目前 Word 包含图文，但不自动 OCR 扫描图；复杂图表、跨文档关联、模型风格保真度需要真人审核。
- 原型缺失的页面只按文字分析，不能声称布局已还原。AI 智能拆页名称必须与原文匹配，不得虚构内容。
- 每个账号的数据隔离，源图与 Style DNA 属于项目数据；项目备份可带走多文档页面状态并重映射素材 ID，不包含账号密钥或模型路由。
- 模型调用仅在人工点击并确认后触发，超时、服务重启不会自动重复付费。图片模型继续复用原工作台。
- 第三方方法参考 MIT 许可的 tnbao91/ai_asset（STYLE、TARGET、CHECK）和 game-ui-design-workflow。无 Unity、切图、图集输出。
- 测试使用独立开发分支和预览环境，正式站不变。真实策划文档与任何 API Key 不上传公开仓库。
